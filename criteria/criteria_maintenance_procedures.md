# 裁定基準（役別）— maintenance_procedures

## 0. 適用と読み込み順序

- 本表は共通コア `criteria.md`（v1.1）に対する **maintenance_procedures 固有の上書き・追加条項**のみを定める。本表に書かれていない点は共通コアに従う
- 共通コアを先に読み、その上に本表を適用する。**競合時は本表を優先**する。ただし本表は共通コアを緩める方向に書かない
- 本表の方針は保守対象の性質に合わせて共通コアの fail-safe より**人間寄り（厳しい側）に具体化する**こと。不可逆な変更が起きやすいため、人間裁定の範囲を広げる
- 適用対象は maintenance_procedures の分解・検収の全行為。配下の実行役（vault / harness / kaizen）は共通コアの実行役規定に従い、本表を直接適用しない

## 1. 対象判定（起票前の最初の判断点）

- 保守系3領域のいずれにも当てはまらない作業を起票しない。所在判定がつかない作業は【裁定：人間】として needs_input で人間に問う（誤配防止）
- 3領域の区分:

| 領域 | 対象 | 絶対前提 |
|---|---|---|
| vault | Obsidian vault ${VAULT_NAME} のノート整理・リネーム・リンク・frontmatter・重複排除 | 9p 配下: in-place 上書き・tmp→rename 禁止 |
| harness | `~/.hermes` 配下の点検・修正・動作確認 | `.env`・鍵ファイルは読み取りも禁止 |
| kaizen | 実行実績の計測・評価・改善提案（Langfuse・state.db 分析） | SELECT のみ・compose/コンテナ/DB 変更禁止 |

## 2. 判断点分類の追加・具体化

| 判断点 | 分類 | 補足 |
|---|---|---|
| criteria / SOUL / config.yaml の改訂適用 | 【裁定：人間】 | 本文に人間承認の明示があるときのみ実行に移す。承認の有無自体が判断点 |
| `.env`・鍵ファイルへの接触 | 判断点にならない（絶対禁止） | 読み取りも含めて禁止。委譲・例外化しない |
| vault 内の大量移動・一括リネーム | 【裁定：人間】 | remotely-save の競合リスク。件数と対象一覧を添えて人間に問う |
| vault 内のファイル名に Obsidian 禁止文字を含める提案 | 判断点にならない（絶対禁止） | 禁止文字セット: `< > : " / \ | ? *`。作らない。既存の禁止文字を含む名前の改名提案は可 |
| `.obsidian/` 配下の変更 | 【裁定：人間】 | 非許可領域 |
| kaizen の DB 書込み・compose/コンテナの変更 | 【裁定：人間】 | SELECT のみ |
| harness の `rm -rf`・プロファイル削除・kanban.db/state.db 直接書込・serve 停止 | 【裁定：人間】 | 実行側は実行せず kanban_comment と成果物に記録して人間へ |
| 保守作業用 workspace の新規作成 | 【裁定：人間】 | 既存実在ディレクトリのみ使用。新規作成は needs_input で人間に問う |
| `hermes gateway restart` の実行 | 【裁量：実行ワーカー】 | 既知手順の範囲のみ。変更後の動作確認と差分を成果物に必須 |
| ノートの細部（frontmatter の項目順・リンクの書式） | 【裁量：実行ワーカー】 | 型に沿う詳細 |

- 本表に無い判断点は共通コアの fail-safe（基準外＝【裁定：人間】）に従う

## 3. 検収の役別確認事項（共通コア §5 への追加）

レビュアーとして呼ばれたとき、共通コアの検収プロセスに加えて:

- 保守系の成果物には**変更前後の差分**（対象一覧・変更点・動作確認結果）が記録されていることを確認する。差分の無い「変更した」申告は不合格
- kaizen の成果物は SQL・数値を成果物に併記していることを確認する。要約のみの申告は不合格
- vault 内の変更は in-place 上書きの手順で行われたことを成果物の手順記述で確認する。残置された `.hermes-tmp.*` の後片付けが成果物に含まれていることを確認する

## 4. 改訂

- 本表の改訂候補は kanban_comment に「改訂候補: criteria_maintenance_procedures.md …」で始まる1文を記録し、人間が本ファイルを改訂する
- 共通コア側の改訂候補は、共通コア §6 のとおり criteria.md 宛に記録する
